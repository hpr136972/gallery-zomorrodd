# سرور، پنل مدیریت و وب‌اپ گالری زمرد (مرحله ۲)

Node.js 22.5+ و SQLite داخلی؛ بدون هیچ وابستگی خارجی.

```bash
cd server
npm test          # ۱۲ تست API
npm start         # http://localhost:3000  | پنل مدیریت: /admin
```
در اجرای اول (حالت توسعه) رمز مدیر اولیه یک‌بار در کنسول چاپ می‌شود. برای تعیین رمز: `ADMIN_USER` و `ADMIN_PASSWORD`.

## متغیرهای محیطی
| نام | توضیح |
|---|---|
| `PORT`, `DB_FILE` | پورت و فایل پایگاه داده |
| `NODE_ENV=production` | سخت‌گیری: `PEPPER` (≥۱۶ نویسه)، `ADMIN_PASSWORD` (≥۱۲)، `DEMO_MODE` غیرفعال |
| `DEMO_MODE=1` | همه سفارش‌ها/قیمت‌ها با `isDemo=true` ثبت می‌شوند (پیش‌فرض در توسعه) |
| `SMS_MODE` | `dev` (کد در پاسخ API؛ فقط توسعه) / `provider` (نیازمند آداپتور) / `off` |
| `GATEWAY_SECRET` | کلید HMAC تأیید پرداخت آنلاین (مرحله ۳) |
| `PRICE_MAX_AGE_MIN` | حداکثر عمر قیمت برای خرید (پیش‌فرض ۷۲۰ دقیقه) |

## قواعد مالی که سرور اعمال می‌کند
- موجودی فقط از «دفتر کل» محاسبه می‌شود و `UNIQUE(order_id)` از اعمال دوباره یک سفارش جلوگیری می‌کند.
- خرید کارت‌به‌کارت فقط با تأیید مدیر؛ خرید آنلاین فقط با فراخوانی امضاشده درگاه (`/api/payments/verify`) و مطابقت مبلغ.
- فروش/تحویل: وزن درخواستی رزرو می‌شود و بیش از موجودی قابل استفاده ممکن نیست؛ کسر موجودی هنگام تأیید مدیر.
- ثبت سفارش با `Idempotency-Key` (جلوگیری از ثبت دوباره).
- OTP: هش‌شده، ۲ دقیقه اعتبار، حداکثر ۵ تلاش، یک کد در دقیقه برای هر شماره.

## محدودیت‌های شناخته‌شده (قبل از استفاده واقعی)
- ارسال پیامک واقعی و درگاه پرداخت واقعی هنوز وصل نیست (مرحله ۳). در حالت `dev` پیامکی ارسال نمی‌شود.
- کدهای چهاررقمی حداکثر ۹۰۰۰ مشتری را پوشش می‌دهند.
- محدودکننده نرخ در حافظه است (برای چند نمونه سرور باید مشترک شود).
- سرور باید پشت HTTPS اجرا شود و از پایگاه داده پشتیبان‌گیری شود.
- بازبینی امنیتی مستقل پیش از پول واقعی لازم است.

## مسیرهای اصلی
مشتری: `POST /api/auth/request-otp`, `/api/auth/verify`, `GET /api/me|portfolio|prices|orders`,
`POST /api/orders/buy|sell|delivery`, `/api/orders/:id/cancel`
مدیر: `POST /api/admin/login`, `GET /api/admin/users|orders|audit`, `POST /api/admin/prices`,
`POST /api/admin/orders/:id/(approve|reject|complete)`

## وب‌اپ مشتریان (PWA)
- آدرس: `/app/` (آدرس `/` به آن هدایت می‌شود). فارسی، راست‌چین و مناسب موبایل؛ به همین سرور وصل است و هیچ منطق مالی‌ای در مرورگر نیست.
- روی گوشی: منوی مرورگر › «افزودن به صفحه اصلی» (Add to Home screen) تا مثل یک برنامه باز شود.
- فعلاً خرید فقط «کارت‌به‌کارت» است (تا تأیید مدیر معلق می‌ماند). پرداخت آنلاین پس از اتصال درگاه فعال می‌شود.
- تست سرتاسری با مرورگر واقعی: `PLAYWRIGHT_PATH=/مسیر/playwright node test/e2e/web.e2e.js`

## استقرار برای استفاده از گوشی
1. آزمایش سریع در خانه: `npm start` روی لپ‌تاپ، سپس در گوشی (همان Wi-Fi) `http://IP-لپ‌تاپ:3000/app/` را باز کنید.
2. استفاده واقعی: سرور (Node 22.5+) روی یک میزبان با دامنه و **HTTPS** و دیسک پایدار (برای فایل `DB_FILE`) اجرا شود و `NODE_ENV=production`، `PEPPER`، `ADMIN_PASSWORD` تنظیم شود. بدون HTTPS اطلاعات کاربران امن نیست.
